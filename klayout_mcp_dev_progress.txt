# KLayout MCP Server Development Progress

## Project Goal
Build a local MCP (Model Context Protocol) Server that exposes KLayout's 2000+ APIs through 4-6 meta-tools, enabling AI agents to interact with KLayout programmatically.

## Architecture Overview
- **Transport**: stdio (standard input/output)
- **Protocol**: MCP (Model Context Protocol)
- **Core Components**:
  1. API Index System - Search and discover KLayout APIs
  2. Document Store - Chunked documentation for context-efficient loading
  3. Handle Registry - Manage KLayout object references (Layout, Cell, etc.)
  4. API Invoker - Reflection-based API execution
  5. Security Layer - Path validation and sandboxing
  6. MCP Tools - 4-6 meta-tools exposing functionality

## MCP Tools (Meta-Tools)
1. `search_klayout_api(query)` - Search APIs by keyword
2. `describe_klayout_api(name)` - Get detailed API documentation
3. `call_klayout_api(name, args)` - Execute API calls
4. `search_klayout_docs(query)` - Search general documentation

## Development Notes

### Key Design Decisions
1. **Meta-tools approach**: Instead of creating 2000+ individual tools, use 4-6 meta-tools that dynamically call KLayout APIs
2. **Dynamic loading**: Load documentation on-demand to keep AI context lightweight
3. **Handle registry**: Maintain references to KLayout objects (Layout, Cell) across API calls
4. **Security**: Implement path validation and sandboxing for file operations
